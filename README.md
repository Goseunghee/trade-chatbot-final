# 🌍 무역 데이터 챗봇 프로젝트

FastAPI와 CSV 데이터를 활용하여 국가별 무역 정보를 자연어 질문 형태로 제공하는 챗봇 및 CRUD API 서비스입니다.

---

## 1. 📌 프로젝트 소개

이 프로젝트는 국가별 무역 데이터를 기반으로 사용자의 질문에 답변하는 챗봇 시스템입니다.
사용자가 예를 들어 `"미국 최신 무역수지 알려줘"`와 같이 입력하면, 해당 국가의 최신 무역 데이터를 찾아 수출, 수입, 무역수지 정보를 반환합니다.

또한 단순 조회 기능뿐 아니라 데이터 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)가 가능한 CRUD API도 함께 구현하였습니다.

---

## 2. 🎯 개발 목적

- ⚙️ FastAPI 기반 백엔드 API 개발 학습
- 📄 CSV 파일을 활용한 데이터 조회 및 관리 기능 구현
- 💬 자연어 질문 처리 기반 챗봇 기능 구현
- 📘 Swagger를 통한 API 문서 자동화 경험
- 🖥️ HTML/CSS/JavaScript를 활용한 간단한 프론트엔드 연동
- 🚀 Render를 활용한 웹 서비스 배포 경험

# 📊 시계열 데이터 분석 및 AI 서비스

## 1. 📌 프로젝트 소개

이 프로젝트는 시계열 데이터를 분석하여 의미 있는 요약 정보를 만들고, 이를 AI 서비스에서 활용하는 과정을 학습하는 것을 목표로 한다.

데이터를 단순히 저장하고 보여주는 것에서 끝나는 것이 아니라,

> **시계열 데이터 수집 → 데이터 분석 → 요약 정보 생성 → Firestore 저장 → FastAPI를 통한 API 제공 → AI 프롬프트에 컨텍스트 주입 → 서비스 활용**

의 전체적인 흐름을 구현하고 이해한다.

---

## 2. 🎯 프로젝트 목표

이번 프로젝트를 통해 다음 내용을 이해하고 설명할 수 있도록 한다.

1. 시계열 데이터를 분석하고 요약 정보를 만들어 서비스에서 활용하는 흐름
2. FastAPI 프로젝트를 Router / Service 등의 역할로 분리하는 이유
3. Pydantic을 이용한 요청 데이터 검증의 필요성과 방법
4. Firestore에 데이터를 저장하고 CRUD로 관리하는 방법
5. 데이터 요약 정보를 시스템 프롬프트에 주입하는 컨텍스트 주입(Context Injection)의 원리
6. 배포 환경에서 CORS, 환경변수, API 키 관리가 필요한 이유

---

## 3. 🔄 전체 시스템 흐름

프로젝트의 전체적인 데이터 흐름은 다음과 같다.

```text
시계열 데이터
     ↓
데이터 전처리
     ↓
시계열 데이터 분석
     ↓
요약 정보 생성
     ↓
Firestore 저장
     ↓
FastAPI API
     ↓
사용자 요청
     ↓
저장된 데이터 요약 조회
     ↓
System Prompt에 Context 주입
     ↓
LLM
     ↓
사용자에게 분석 결과 제공
```

예를 들어 특정 기간의 데이터를 분석하여 다음과 같은 요약 정보를 만들 수 있다.

- 📈 최근 데이터가 증가하는 추세
- 🔝 특정 기간에 가장 높은 값이 발생
- ⬆️ 평균값보다 최근 값이 높은 상태
- 📊 이전 기간 대비 증가율이 상승

이렇게 만들어진 요약 정보를 AI에게 제공하면 AI가 단순한 일반 지식이 아니라 현재 서비스의 실제 데이터에 기반하여 답변할 수 있다.

---

## 4. 📉 시계열 데이터 분석

### 4-1. 시계열 데이터란?

시계열 데이터(Time Series Data)는 시간의 흐름에 따라 순서대로 기록된 데이터이다.

예를 들어 다음과 같은 데이터가 있다.

| 날짜 | 값 |
|---|---|
| 2026-01-01 | 100 |
| 2026-01-02 | 120 |
| 2026-01-03 | 115 |
| 2026-01-04 | 140 |
| 2026-01-05 | 160 |

각 데이터가 시간 순서대로 존재하기 때문에 일반적인 데이터와 달리 시간에 따른 변화와 추세를 분석할 수 있다.

### 4-2. 시계열 데이터에서 확인할 수 있는 정보

시계열 데이터를 분석할 때 다음과 같은 정보를 확인할 수 있다.

**📐 평균**

전체 데이터의 평균적인 값을 확인한다.

```
평균 = 전체 값의 합 / 데이터 개수
```

**🔺 최대값 / 🔻 최소값**

특정 기간 동안 가장 높은 값과 가장 낮은 값을 확인한다.

**📈 추세(Trend)**

시간이 지나면서 데이터가 증가하는지 감소하는지 확인한다.

```
100 → 120 → 130 → 150
```

위와 같은 경우 전체적으로 증가하는 추세라고 볼 수 있다.

**🔁 변화량**

이전 데이터와 비교하여 얼마나 증가하거나 감소했는지 확인한다.

```
현재 값 - 이전 값
```

**📊 변화율**

이전 값과 비교하여 비율로 얼마나 변화했는지 확인한다.

```
(현재 값 - 이전 값) / 이전 값 × 100
```

## 5. 📝 데이터 요약 정보 생성

분석한 시계열 데이터는 서비스에서 활용하기 쉽게 요약 정보로 만들 수 있다.

예를 들어 원본 데이터가 다음과 같다면,

```json
{
  "date": "2026-01-01",
  "value": 100
}
```

여러 데이터를 분석하여 다음과 같은 요약 정보를 만들 수 있다.

```json
{
  "average": 125.4,
  "maximum": 180,
  "minimum": 90,
  "trend": "increasing",
  "change_rate": 12.5
}
```

이렇게 하면 서비스에서는 매번 모든 원본 데이터를 다시 분석하지 않고도 요약 정보를 활용할 수 있다.

즉,

```text
원본 데이터
    ↓
분석
    ↓
핵심 정보 추출
    ↓
요약 데이터
    ↓
서비스에서 활용
```

의 구조로 처리할 수 있다.

## 6. ⚙️ FastAPI 프로젝트 구조

FastAPI 프로젝트에서는 모든 코드를 하나의 파일에 작성하기보다 역할에 따라 여러 파일로 분리할 수 있다.

예시 구조는 다음과 같다.

```text
project/
│
├── main.py
│
├── routers/
│   ├── data.py
│   └── summary.py
│
├── services/
│   ├── analysis_service.py
│   └── firestore_service.py
│
├── schemas/
│   └── data_schema.py
│
├── database/
│   └── firestore.py
│
└── .env
```

### 6-1. 🚦 Router

Router는 클라이언트의 HTTP 요청을 받아 적절한 기능으로 연결하는 역할을 한다.

예를 들어,

```text
GET /data
POST /data
GET /summary
```

와 같은 API의 엔드포인트를 관리한다.

Router에서는 복잡한 분석이나 데이터베이스 작업을 직접 처리하기보다 Service에 작업을 요청한다.

```text
Client
  ↓
Router
  ↓
Service
  ↓
Database
```

### 6-2. 🧩 Service

Service는 실제 비즈니스 로직을 담당한다.

예를 들어 시계열 데이터의 경우,

```text
데이터 조회
↓
데이터 분석
↓
평균 계산
↓
최대/최소값 계산
↓
추세 분석
↓
요약 정보 생성
```

등의 작업을 Service에서 처리할 수 있다.

이렇게 하면 Router가 복잡해지는 것을 방지할 수 있다.

### 6-3. 🧠 역할을 분리하는 이유

역할을 분리하면 코드의 유지보수가 쉬워진다.

예를 들어 분석 방법을 변경해야 하는 경우에도 Router 코드를 수정하지 않고 Service 부분만 수정할 수 있다.

또한 각각의 기능을 독립적으로 테스트하기 쉬워진다.

| 구성 요소 | 역할 |
|---|---|
| 🚦 Router | API 요청 처리 |
| 🧩 Service | 실제 프로그램 로직 처리 |
| 🗄️ Database | 데이터 저장 및 조회 |
| 🧪 Schema | 요청 데이터 검증 |

## 7. 🧪 Pydantic을 이용한 데이터 검증

### 7-1. Pydantic이란?

Pydantic은 Python에서 데이터의 구조와 타입을 검증할 수 있도록 도와주는 라이브러리이다.

FastAPI에서는 요청 데이터의 검증을 위해 Pydantic 모델을 많이 사용한다.

예를 들어 다음과 같은 요청 데이터를 받는다고 가정한다.

```python
from pydantic import BaseModel

class DataRequest(BaseModel):
    date: str
    value: float
```

클라이언트가 보내는 데이터가 다음과 같은 구조인지 확인할 수 있다.

```json
{
  "date": "2026-01-01",
  "value": 120.5
}
```

### 7-2. Pydantic을 사용하는 이유

사용자가 API에 잘못된 데이터를 보내는 것을 방지하기 위해 사용한다.

예를 들어 숫자가 들어가야 하는 value에 잘못된 문자열이 들어온 경우 데이터를 검증할 수 있다.

```json
{
  "date": "2026-01-01",
  "value": "abc"
}
```

이러한 요청을 그대로 데이터베이스에 저장하면 오류가 발생할 수 있다.

따라서 API의 입구에서 데이터를 검증한다.

```text
사용자 요청
   ↓
Pydantic 검증
   ↓
정상 데이터 → Service
   ↓
잘못된 데이터 → 오류 응답
```

이를 통해 API가 예상하지 못한 데이터를 처리하는 문제를 줄일 수 있다.

## 8. 🔥 Firestore

### 8-1. Firestore란?

Firestore는 Firebase에서 제공하는 NoSQL 클라우드 데이터베이스이다.

프로젝트에서는 분석한 시계열 데이터와 요약 정보를 저장하는 용도로 사용할 수 있다.

기본적인 구조는 다음과 같다.

```text
Firestore
│
├── collection
│      └── document
│             ├── date

```

## 9. 🔧 Firestore CRUD

CRUD는 데이터베이스에서 가장 기본적인 네 가지 작업을 의미한다.

- **C** = Create ➕
- **R** = Read 🔍
- **U** = Update ✏️
- **D** = Delete 🗑️

**➕ Create**

새로운 데이터를 저장한다.

```text
사용자 데이터
      ↓
Firestore에 저장
```

예:

```json
{
  "date": "2026-01-01",
  "value": 120
}
```

**🔍 Read**

Firestore에 저장된 데이터를 조회한다.

예:

```text
GET /data
```

API 요청을 보내면 Firestore에 저장된 데이터를 가져올 수 있다.

**✏️ Update**

기존 데이터를 수정한다.

예를 들어,

```text
value: 120
```

을

```text
value: 150
```

으로 변경할 수 있다.

**🗑️ Delete**

더 이상 필요하지 않은 데이터를 삭제한다.

```text
DELETE /data/{id}
```

와 같은 API를 통해 특정 데이터를 삭제할 수 있다.

**🔁 CRUD 전체 흐름**

```text
Create → 데이터 생성
Read   → 데이터 조회
Update → 데이터 수정
Delete → 데이터 삭제
```

FastAPI와 Firestore를 연결하면 웹 서비스에서 데이터베이스를 API 형태로 사용할 수 있다.

## 10. 🧠 컨텍스트 주입(Context Injection)

### 10-1. 컨텍스트 주입이란?

컨텍스트 주입은 서비스에서 가지고 있는 데이터를 AI의 프롬프트에 추가하여 AI가 해당 정보를 참고하도록 만드는 방법이다.

특히 데이터 분석 서비스에서는 매우 중요한 방식이다.

예를 들어 데이터 분석 결과가 다음과 같다고 가정한다.

```text
최근 평균값: 135
최대값: 180
최소값: 90
최근 변화율: +12.5%
추세: 증가
```

이 정보를 AI의 시스템 프롬프트에 포함한다.

```text
[시스템 프롬프트]

너는 데이터 분석 도우미이다.

현재 데이터 요약:
- 평균값: 135
- 최대값: 180
- 최소값: 90
- 최근 변화율: +12.5%
- 추세: 증가

위 데이터를 참고하여 사용자의 질문에 답변하라.
```

사용자가 질문하면 AI는 위의 데이터를 참고하여 답변한다.

### 10-2. 컨텍스트 주입의 흐름

```text
Firestore
    ↓
데이터 조회
    ↓
시계열 데이터 분석
    ↓
요약 정보 생성
    ↓
System Prompt에 삽입
    ↓
LLM 요청
    ↓
AI 답변
```

이 방식의 장점은 AI에게 매번 모든 원본 데이터를 전달하지 않고 필요한 핵심 정보만 요약하여 전달할 수 있다는 것이다.

---

## 11. ❓ 왜 시스템 프롬프트에 데이터를 넣는가?

일반적인 AI에게 질문하면 AI는 서비스에서 관리하는 최신 데이터를 알 수 없다.

예를 들어 사용자가 다음과 같이 질문한다고 하자.

> 현재 데이터의 추세가 어떻게 돼?

AI에게 실제 데이터 요약을 제공하지 않는다면 정확한 분석이 어렵다.

하지만 시스템 프롬프트에 다음과 같은 정보를 넣으면,

```text
추세: 증가
최근 변화율: +12.5%
```

AI가 실제 서비스 데이터를 기반으로 답변할 수 있다.

따라서 컨텍스트 주입은

> **서비스의 데이터와 AI의 자연어 처리 능력을 연결하는 방법**

이라고 이해할 수 있다.

## 12. 🌐 CORS

### 12-1. CORS란?

CORS(Cross-Origin Resource Sharing)는 서로 다른 출처(Origin)의 웹 페이지가 API 서버에 요청할 수 있도록 허용하는 정책이다.

예를 들어,

```text
프론트엔드
https://my-service.com
        ↓ API 요청
FastAPI 서버
https://api.my-service.com
```

처럼 프론트엔드와 백엔드의 주소가 서로 다를 수 있다.

이때 서버에서 적절한 CORS 설정을 하지 않으면 브라우저가 요청을 차단할 수 있다.

### 12-2. 배포 환경에서 CORS가 필요한 이유

개발 환경에서는 다음과 같이 실행할 수 있다.

```text
Frontend
localhost:3000

Backend
localhost:8000
```

두 서버의 Origin이 다르기 때문에 CORS 설정이 필요할 수 있다.

배포 후에도 프론트엔드와 백엔드가 서로 다른 도메인을 사용한다면 CORS 설정이 필요하다.

따라서 실제 서비스를 배포할 때는 허용할 Origin을 정확하게 설정해야 한다.

## 13. 🔑 환경변수 관리

API 키나 데이터베이스 인증 정보 같은 중요한 정보는 코드에 직접 작성하지 않는 것이 좋다.

**❌ 잘못된 예:**

```python
API_KEY = "실제_API_KEY"
```

이렇게 작성하면 GitHub 등에 코드가 공개될 경우 API 키가 노출될 수 있다.

대신 환경변수를 사용한다.

```text
환경변수
    ↓
API_KEY
DATABASE_URL
SECRET_KEY
```

Python에서는 환경변수를 읽어서 사용할 수 있다.

```python
import os

api_key = os.getenv("API_KEY")
```

## 14. 🔒 API 키를 안전하게 관리해야 하는 이유

API 키가 외부에 노출되면 다른 사람이 해당 키를 사용할 수 있다.

그 결과,

- 💸 예상하지 못한 API 사용량 발생
- 💰 비용 발생
- 🛡️ 서비스 보안 문제
- 🔓 데이터 접근 문제
- ♻️ API 키 폐기 및 재발급 필요

등의 문제가 발생할 수 있다.

따라서 API 키는 소스 코드에 직접 작성하지 않고 환경변수나 배포 플랫폼의 Secret 기능 등을 이용해 관리한다.

또한 `.env` 파일은 Git에 업로드하지 않도록 `.gitignore`에 추가한다.

```text
.env
```

## 15. 🚀 배포 환경에서 필요한 설정

개발 환경과 실제 배포 환경은 다를 수 있다.

```text
개발 환경
localhost
    ↓
테스트

배포 환경
실제 도메인
    ↓
실제 사용자
```

따라서 배포할 때 다음과 같은 설정을 확인해야 한다.

**🌐 CORS**

프론트엔드에서 백엔드 API를 정상적으로 호출할 수 있도록 설정한다.

**🔑 환경변수**

API 키, Firebase 설정 등 민감한 정보를 안전하게 전달한다.

**🔒 API 키**

소스 코드에 노출하지 않고 서버의 환경변수 또는 Secret으로 관리한다.

**🗄️ 데이터베이스**

배포 서버에서도 Firestore에 정상적으로 접근할 수 있는지 확인한다.

## 17. 📚 핵심 학습 내용 정리

### ① 📉 시계열 데이터 분석

시간 순서에 따라 데이터를 분석하여 평균, 최대값, 최소값, 변화율, 추세 등의 정보를 얻는다.

```text
시계열 데이터
→ 분석
→ 요약 정보
→ 서비스 활용
```

### ② ⚙️ FastAPI 구조 분리

Router, Service, Database 등의 역할을 분리하여 코드의 가독성과 유지보수성을 높인다.

```text
Router → 요청 처리
Service → 비즈니스 로직
Database → 데이터 저장/조회
Schema → 데이터 검증
```

### ③ 🧪 Pydantic

API 요청 데이터가 올바른 구조와 타입을 가지고 있는지 검증한다.

```text
요청
→ Pydantic 검증
→ 정상 데이터만 Service로 전달
```

### ④ 🔧 Firestore CRUD

Firestore를 이용하여 데이터를 생성, 조회, 수정, 삭제할 수 있다.

- ➕ Create
- 🔍 Read
- ✏️ Update
- 🗑️ Delete

### ⑤ 🧠 Context Injection

시계열 데이터를 분석하여 만든 요약 정보를 System Prompt에 넣어 AI가 실제 서비스 데이터를 참고하도록 한다.

```text
데이터
→ 분석
→ 요약
→ System Prompt
→ LLM
→ 답변
```

### ⑥ 🚀 배포 환경

실제 서비스에서는 CORS, 환경변수, API 키 관리가 중요하다.

| 항목 | 설명 |
|---|---|
| 🌐 CORS | 프론트/백엔드 통신 허용 |
| 🔑 환경변수 | 설정값 관리 |
| 🔒 API Key | 민감정보 보호 |

## 18. 🎤 발표/시험에서 설명할 수 있는 핵심 문장

**Q. 시계열 데이터 분석의 흐름은?**

시계열 데이터를 시간 순서대로 수집하고 전처리한 뒤 평균, 최대값, 최소값, 변화율, 추세 등을 분석합니다. 분석 결과를 요약 정보로 만들어 데이터베이스에 저장하고, 이후 서비스나 AI가 활용할 수 있도록 합니다.

**Q. FastAPI를 Router와 Service로 나눈 이유는?**

Router는 API 요청과 응답을 담당하고 Service는 실제 비즈니스 로직을 담당하도록 역할을 분리했습니다. 이렇게 하면 코드가 복잡해지는 것을 막고 유지보수와 테스트가 쉬워집니다.

**Q. Pydantic을 사용하는 이유는?**

API로 들어오는 요청 데이터의 타입과 구조를 검증하기 위해 사용합니다. 잘못된 데이터가 Service나 데이터베이스까지 전달되는 것을 방지할 수 있습니다.

**Q. Firestore CRUD란?**

Create, Read, Update, Delete의 약자로 데이터를 생성, 조회, 수정, 삭제하는 기본적인 데이터 처리 작업입니다.

**Q. 컨텍스트 주입이란?**

서비스에서 분석한 데이터 요약 정보를 System Prompt에 추가하여 LLM이 실제 서비스 데이터를 참고하면서 답변하도록 만드는 방식입니다.

**Q. 배포할 때 CORS가 필요한 이유는?**

프론트엔드와 백엔드의 출처가 다를 경우 브라우저의 보안 정책 때문에 API 요청이 차단될 수 있기 때문에 허용할 출처를 CORS로 설정해야 합니다.

**Q. API 키를 환경변수로 관리하는 이유는?**

API 키를 코드에 직접 작성하면 GitHub 등에 노출될 위험이 있기 때문에 환경변수나 Secret으로 관리하여 보안을 유지합니다.

## 19. 🏁 최종 정리

이 프로젝트에서 가장 중요한 개념은 **데이터 → 분석 → 요약 → 저장 → API → AI**로 이어지는 흐름이다.

```text
📊 시계열 데이터
      ↓
🔎 데이터 분석
      ↓
📝 요약 정보 생성
      ↓
🔥 Firestore 저장
      ↓
🚀 FastAPI API
      ↓
🧠 Context Injection
      ↓
🤖 LLM
      ↓
💬 사용자에게 답변
```

이를 통해 단순히 데이터를 저장하는 서비스가 아니라, **실제 데이터를 분석하고 그 결과를 AI가 활용할 수 있도록 연결하는 데이터 기반 AI 서비스의 기본 구조**를 이해할 수 있다.
